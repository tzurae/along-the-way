## 1. 問題與預期結果

只有一句推薦語，無法回答旅客實際需要的「為什麼去、看什麼、怎麼去、參觀要注意什麼」。加入照片後，如果切圖會改變署名區高度，正文就會上下跳動；如果照片資訊另有阻止捲動的區域，使用者也可能無法順手讀到詳情底部。

正式功能應讓成員從 AI 建議、口袋名單與今天的地點入口，在原畫面開啟同一地點的內容與照片；切圖不移動正文，照片資訊不攔截垂直捲動，文字與既有操作不等待圖片載入。事實與照片都能追溯各自來源，未知內容不靠編造補齊。

本文件是功能規格，不是資料庫 migration、API schema 或施工計畫。後續實作應沿用既有地點、旅程地點與來源契約，不以本文件的資料名稱建立第二套地點模型。

## 2. 已確認與新增規格的界線

### 已確認的體驗

1. 採 B 版：清單有小縮圖，詳情有可左右滑動的多張照片；不沿用 A／C 版的其他清單結構。
2. 照片可放大查看；照片資訊必須對應目前看到的那張照片。
3. 詳情的照片資訊以固定 56px 區域低調呈現；作者、來源、授權與「照片資訊」入口保留，不以隱藏署名換取簡潔。
4. 56px 區域屬於詳情正文的捲動流，不自成垂直捲動區；切圖不擠動下一段正文。完整資訊由既有照片檢視器呈現。
5. 景點內容用小標題、短段落與條列，包含實質介紹、看點、地址、交通、時間、費用與注意事項；時間和費用是有日期的參考，不是出遊當天保證。
6. 未知咖啡店只列待確認資訊，不虛構店名、位置、照片或營業狀況。

### 本文件新增、待審閱的正式要求

- 可重用照片的逐張資料、查核與保存要求。
- 無照片、只有一張、載入失敗、超長署名及資料過期的具體處理。
- 三個入口使用同一地點內容的要求與正式驗收情境。

以上要求不得描述成已存在的正式功能。POC 內的本機資料與模擬操作不能當成後端、多人同步或正式授權處理已完成的證據。

## 3. 範圍

### 納入

- 景點詳情的可掃讀內容、來源、查核日期與未知／需要重新確認標示。
- 地點清單縮圖、詳情照片相簿、放大檢視與逐張署名。
- 有可核對授權、能對應正確地點的策展照片；初始來源採 Wikimedia Commons 的逐張檔案頁，並非 Google Maps 網頁圖片。
- AI 建議、口袋名單、今天三個已選定入口的內容一致性；既有頁面自己的推薦理由、加入原因與行程操作保留原責任。
- 手機與桌面正常捲動、缺圖與失敗時仍能閱讀內容。

### 不納入

- 旅程相簿、使用者照片上傳、評論、旅遊文章與社群功能。
- 抓取 Google Maps 網頁圖片、永久複製 Google Places 受限制內容，或新增 Google Place Photos 整合。
- 任意地點的完整自動研究、批次搜圖／自動刊登照片、生成式圖片或用別的地點湊圖。
- 修改投票、排程、時間設定、導航規劃或成員權限。
- 新的媒體管理後台、儲存供應商遷移或獨立服務。

舊 MVP 規格提到 Google Place Photos；本次照片功能以本文件的可重用授權策展照片為界線，不把舊文的 Google 照片構想視為本次授權。`PRODUCT.md` 的既有無障礙基準不變；先前 POC 排除無障礙檢查，不等於取消正式產品的基準。

## 4. 用語與內容責任

| 用語 | 責任與界線 |
| --- | --- |
| 地點 | 可辨識的實際場所；沿用既有地點識別，不以顯示名稱當唯一識別。同名分店不可混用內容或照片。 |
| 旅程地點 | 地點在某趟旅程中的加入原因、成員資訊與排程狀態；不能被景點介紹覆蓋。 |
| 景點內容 | 描述場所本身的介紹、看點與參觀資訊；不是推薦分數、成員的想去原因或已確認行程。 |
| 內容來源 | 支持一段具體事實的原始頁面；有查核時間及適用期間資訊，不能只附網站首頁。 |
| 照片 | 一張獨立作品，包含自己的地點對應、作者、授權、來源及顯示順序；不能共用整組相簿的一份署名。 |
| 查核日期 | 實際核對來源的日期；不是文章發布日、圖片拍攝日、頁面開啟日或資料保證有效日。 |
| 適用期間 | 來源明確支持的日期範圍，例如特別展覽、季節票價或夜間開放；未知就保持未知。 |

景點內容沿用既有 Place Detail「組合第一方內容、官方來源與供應商資料並執行 attribution」的責任。供應商受限資料不因寫入新內容欄位而變成可永久保存的第一方資料。

## 5. 閱讀與照片操作

### 清單 → 詳情

- 小縮圖只補充辨識，不取代名稱、類型與既有文字；不引入新的列表版型。
- 開啟詳情留在當前頁面。手機與桌面使用既有 sheet／panel，不另外新增景點文章頁。
- 三個入口取得同一地點的內容與照片；AI 的「為什麼推薦」、口袋名單的「為什麼想去」、今天的行程時間仍各自呈現，不混成同一段介紹。
- 關閉詳情返回原清單及原捲動位置；觀看照片不改投票、加入原因或排程。

### 詳情相簿

- 以實際可用的照片數量顯示「目前張數／總張數」，順序由資料提供，不寫死三張或特定京都地點。
- 手機支援原生左右滑動；桌面有上一張／下一張操作。第一張、最後一張的邊界操作不可越界。
- 單張照片不提供假裝能切換的控制；零張照片不顯示空相簿控制。
- 切圖更新目前照片、計數、作者、來源、授權及照片資訊入口，不能先切圖片卻仍顯示上一張署名。
- 相簿圖片區與 56px 資訊區有穩定尺寸；圖片比例或署名長度不同都不擠動正文。
- 56px 區域顯示精簡署名；超長內容不溢出、不增加區域高度，完整資料由「照片資訊」入口取得。若某張作品的授權條件無法在此結構完整履行，該照片不得納入。
- 滑鼠位於照片資訊或正文上時，垂直滾輪都帶動詳情正文；手機在資訊列上垂直滑動也能閱讀下方內容。只有照片相簿處理左右切圖，不以鎖住垂直捲動避免誤觸。

### 放大檢視／照片資訊

- 點照片或「照片資訊」，開啟目前照片的檢視器，不跳回第一張。
- 大圖保留完整構圖，並可讀取作品標題／說明、作者及作者連結（若有）、原始作品頁、授權名稱與連結、拍攝日期（若有）、修改說明及其他必須保留的聲明。
- 明確區分歷史拍攝日期與查核日期；照片不被描述成當日實景。
- 關閉檢視器保留詳情目前照片及正文位置，不重建成另一個地點。
- 現有 Google Maps 外部連結保留；位置未知時不製造看似確定的導航目的地。

## 6. 景點敘述

### 內容組織

照片之後呈現有實質資訊的段落，使用以下內容分類；不是每個地點必須塞滿全部欄位：

1. **景點介紹**：這是什麼地方，以及具體值得考慮的原因。
2. **主要看點**：實際可看的建築、庭園、展示或特色；不以「很棒」「必去」替代理由。
3. **地址與交通**：可核對的完整地址、交通起點、路線／站點與最後一段步行說明。交通耗時標明來源與參考性，不當成即時 Routes 結果。
4. **開放時間與費用**：時段、休息／特殊開放情況、票種、幣別與適用日期；免費必須有依據，未知不顯示零元。
5. **參觀注意事項**：預約、不同區域是否另收費、樓梯／坡道、天候、拍攝限制等有來源的具體資訊。
6. **來源與查核日期**：事實能對應到支持它的來源；重要時間／價格／季節限制在該段標示，不能只藏在頁尾的總免責文字。

### 未知與衝突

- 資料有缺口時直接說明，例如「開放時間尚未確認」「門票待確認」。不生成內容來滿足篇幅要求。
- 有用內容保留；不適用的內容分類不渲染空標題。
- 未能辨識場所的手動項目，例如「沿途看到的咖啡店」，只呈現使用者原文與待確認項目，不猜測某間店。
- 官方網站和旅遊資料給出不同價格／時段時，並列出差異、來源與日期，標為「資料不一致，需要確認」；不無聲挑選一筆。
- 從公開事實自行整理具體敘述，不複製整篇受保護文章。引用或重用文字仍須符合該來源條件；有來源連結不等於擁有全文轉載權。

## 8. 取得照片與授權

1. 初始採經逐張核對的 Wikimedia Commons 照片。取得方式可使用檔案頁及 Commons API 查資料，但搜尋命中與 metadata 本身不是授權／地點正確性的保證。
2. 納入前核對作品頁、真正作者、選用授權與版本、必須保留的署名、地點、其他限制，以及本產品的保存／顯示方式是否符合條件。條件不明或無法履行就不使用。
3. 可依法重用的照片可下載並由產品供應圖片；作品頁與授權資料仍保留。正式檔案儲存與部署另在實作 scope 指定，不把 `/tmp/along-ai-prototype/photo-assets/` 當正式儲存位置。
4. 各張作品依自己的授權呈現。CC BY-SA 的實際改作須符合同授權分享及修改標示等條件；不能因 CSS 預覽裁切而宣稱所有後續加工都不算改作。
5. 清單預覽可裁切，放大圖提供完整構圖與該作品署名；不移除浮水印或必要聲明來配合視覺。
6. 不下載 Google Maps 網頁照片後換成 Commons 署名，也不把 Google Maps 的外部連結當照片重用授權。
7. 作品頁公開授權不保證肖像、隱私、商標等所有權利均已處理；有已知限制且無法確認本用途適用時，使用無照片狀態。
8. 不為了湊成三張而使用錯誤場所、重複作品或未查核圖片。已核對一張就顯示一張，零張則無照片。

授權依據見第 12 節。這是產品的納入規則，不是對所有 Commons 檔案的法律保證。

## 9. 資料有效性與異常狀態

「查核過」與「出遊當日有效」是兩件事。只有來源明確支持的期間能顯示為適用期間；沒有期限不可自行加上一個有效期，也不可解讀成永久有效。

以下情形標「需要重新確認」：已知來源可用期限已過，或旅程日期不在已查到的適用期間內。來源有明確修正／衝突時呈現修正或衝突，不用改查核日期掩蓋變更。沒有適用期間的公開時間／票價，以查核日期與「公開資訊參考，出遊前請確認」呈現，不保證旅程日期可用。

| 情境 | 可觀察結果 |
| --- | --- |
| 沒有合適照片／授權資料缺漏 | 清單不顯示破圖；詳情顯示低存在感「尚無可用照片」，無切圖／放大控制；文字仍可閱讀。 |
| 只有一張照片 | 顯示單張及正確署名，沒有可用的上一張／下一張；可放大。 |
| 圖片仍在載入 | 預留穩定尺寸；正文、來源和既有操作先可使用，不全頁等圖片。 |
| 某張圖片載入失敗 | 該張位置顯示「照片暫時無法載入」；不顯示別張作品配該張署名，可切換其他張；無可用大圖就不提供假放大操作。 |
| 照片來源頁暫時不可用 | 已核對且可合法保存的圖片與署名可繼續顯示；不聲稱剛重新查核，也不把頁面故障推論為授權被撤回。 |
| 景點資料未知 | 呈現已知資訊與具體待確認項目；未知地址不產生確定目的地的 Maps 連結。 |
| 時間／價格／活動已知過期或不適用旅程日期 | 舊值如保留則明確標成先前參考，附近顯示「需要重新確認」及來源日期；不標為目前已確認。 |
| 無網路或來源服務故障 | 第一方／依法保存的內容依既有可用資料呈現；受限即時資料按原政策顯示不可用，照片失敗不影響閱讀。不得承諾本次新增完整離線相簿。 |
| 作者／作品名很長或手機字級放大 | 56px 區域與正文位置穩定，必要完整資料可從照片資訊讀取；連結可操作，不橫向溢出。 |

失敗不影響已確認行程，也不觸發自行重排、移除地點或投票變動。

## 10. 正式驗收條件

下列是正式功能的行為驗收清單，要求維持不變。本次使用已批准的獨立資料與 25100 環境，已直接觀察主要情境；修後結果及剩餘驗證以 [工程驗收紀錄](../../engineering/place-details-and-photos.md#驗收與追蹤) 為準。測試數或程式閱讀不能取代真實介面證據。

| 編號 | 情境與操作 | 必須觀察到的結果 |
| --- | --- | --- |
| A01 | 同一測試地點分別從 AI 建議、口袋名單、今天開啟 | 地點內容、照片作品與各張署名一致；各入口原有的推薦／加入原因／行程時間不被替換。 |
| A02 | 從有三張不同作者／授權的地點清單開啟詳情 | 縮圖、首張、作品頁與署名對應；沒有地點名稱特殊判斷。 |
| A03 | 手機左右滑動 1 → 2 → 3 → 2 → 1 | 圖片、計數、署名、來源、授權及照片資訊對應當前張；下一段正文位置不移動。 |
| A04 | 桌面使用上一張／下一張至兩端 | 選擇正確，邊界不可越界；不出現不存在的照片或上一張的署名。 |
| A05 | 第二張按照片資訊，再關閉 | 檢視器為第二張，完整資料與完整構圖可讀；回到同一張、同一正文位置。 |
| A06 | 零張、一張、兩張與多張地點各開一次 | 控制與實際數量一致，不湊圖、不寫死三張；零張仍讀得到內容。 |
| A07 | 在 320px、390px、1440px 使用足以超出畫面的長內容 | 頁面與詳情沒有橫向捲動；正文能捲到最後的來源和提醒，不被底部操作遮住。 |
| A08 | 滑鼠放在照片資訊列／正文上分別滾輪；手機在資訊列上垂直滑動 | 都可帶動詳情正文；向下到最後、向上回頭均正常，資訊列不成為捲動陷阱。 |
| A09 | 有長作者、多位作者、長授權聲明或放大字級時切圖 | 56px 區域不膨脹、不擠動正文；完整必要資訊可從入口讀取，不能靠隱藏它通過。 |
| A10 | 限制圖片網路或使其中一張圖片回傳失敗 | 正文先可讀；失敗位置不破圖、不混署名；其他照片可觀看，行程操作不被圖片阻塞。 |
| A11 | 在未知咖啡店及同名不同分店間切換詳情 | 未知店不出現編造內容／導航；不同分店不共用另一家的照片或地址。 |
| A12 | 查核有不同作者、不同授權版本及 CC0 的照片 | 每張作品頁、作者、授權連結和修改說明正確；不以相簿固定署名取代逐張資料。 |
| A13 | 提供已過可用期限或不涵蓋旅程日期的時間／費用來源 | 舊值不被稱為當日有效；原來源、查核日期及「需要重新確認」可讀。 |
| A14 | 提供互相衝突的兩份公開來源 | 差異與各來源日期可見，不自行選值當真相；不修改成員已確認行程。 |
| A15 | 關閉照片檢視器，再關閉詳情 | 回到原清單位置；投票、加入原因、排程與行程版本沒有因閱讀而改動。 |
| A16 | 以非京都、不同日期及不同張數的另一測試地點操作 | 同樣完整流程成立，沒有京都名稱、三位成員或旅程日期的分支。 |
| A17 | 執行 `PRODUCT.md` 既有無障礙基準 | 鍵盤可操作開啟、切換與關閉，焦點回到合理入口；新增內容不使既有對比、觸控與 reduced-motion 基準倒退。 |

授權查核不只驗證畫面連結：本次逐張對照十份 Commons 永久版本及二十個官方衍生檔；三入口、原生手機滑動、圖片網路失敗、日期／衝突與核心唯讀狀態已有隔離證據。獨立審查曾指出快照遷移寫入失敗會刪除可讀資料、清單位置證據不足、既有按鈕對比及 CI 入口缺漏；修復與最終處置見工程驗收紀錄，不以舊 PASS 掩蓋新發現。
